## Picking this up on another machine

Work lands on `main` through feature branches; `git branch -a` shows any not merged yet.

1. `git clone https://github.com/RMamujee/LowRange.git`, then `npm ci` (Node 20+; built and tested here on Node 22 and 24).
2. `npm run dev` serves http://localhost:5199. Maps: pick in the menu or with `?map=park|race|crawl|jungle|desert` (park is the default).
3. Set the commit identity in the new clone before the first commit, so a private address never reaches this public repo:
   `git config user.name RMamujee` and `git config user.email 133895954+RMamujee@users.noreply.github.com`.
4. Pushing to `main` deploys to https://lowrange.vercel.app (Vercel project `lowrange`, Vite preset, `npm run build`, output `dist`). Nothing to set up per machine.
5. Blender (only for art work): Blender 5.3 with the official Blender Lab MCP add-on (`mcp`, listens on localhost:9876 while Blender's GUI is open, needs Preferences > System > Allow Online Access), plus its MCP server registered with the coding agent. This is per machine and not in the repo. Do not install the PyPI package `blender-mcp`: that is the community server, a different protocol. The `.blend` sources are in `art/blender/`.
6. If the game loads headless but fails in your own browser, suspect an ad blocker matching a file name (see `test/blocklist_names.mjs`).

## Ride and damping

The suspension force model now lives in `src/ride.js` (pure maths, no Rapier) and is applied by `rideStep()` in `src/vehicle.js` (marked `[ride]`) to the suspension joint motors every step: target, stiffness and damping, linearised about each joint's position and speed, so Rapier still integrates it implicitly (stable at any rate). `node test/ride.mjs` measures and checks it (about 6 min; `RIDE_BASE=<dir with an older src/>` prints before / after side by side; `RIDE_CASES=whoops,...` picks driving cases).

**What caused the bounce (measured at the old stock settings):**
- Linear, symmetric dampers at zeta 0.30-0.36 in both directions. Released from a 30-40 mm push the body overshot 30-37% and swung 3 half-cycles before it was within 5 mm (0.8 s on the Cruiser). Real dampers have 1.5-3x the bump damping in rebound.
- Hard, elastic travel limits. Landings hit Rapier's joint limit at 1-1.5 m/s; the limit pushes the joint back out of its overlap and hands energy back. Drops gained energy: Cruiser +5.4% of the drop energy at 0.5 m and +8.1% at 1 m, Pickup +2.8% / +4.8%, Sedan +2.2% / +2.9%. After a bottom-out the body rebounded 38-50% (0.3-0.5 m drops) and 63-75% (1 m) of the compression.
- No bump stop and no droop strap: the only end stops were the hard limits above.
- Restitution: tyres and body boxes had 0 but the Average rule, so on the 0.2 props (bridges, rails, huts) they bounced at 0.1. Rocks and ground were already 0.
- Rigid tyres: Rapier's tyre collider has no vertical compliance, so there is no wheel-hop mode; a tyre hitting a sharp edge at speed gets its velocity changed in one step. This is still so (see Known limits).
- Not causes: no explicit spring force anywhere (the anti-roll bar impulse is small and stable), solver iterations / substeps (8 at 200 Hz), tyre landings on rock (hop under 4 mm, which is the engine pushing a tyre that sank in a few mm back out).

**Reference values used:** ride frequency 1.2-1.6 Hz for trucks (rear a little above front), 1.6-2.2 Hz for the rally car; damping ratio about 0.25-0.35 bump and 0.4-0.6 rebound (trucks), a little higher for the rally car; settled within 1-1.5 cycles, overshoot under 25-30%; tyre vertical rate 200-300 N/mm at road pressure; near-zero restitution; progressive, lossy bump stops and a soft droop limit.

**The new model (spec data per rig in `src/specs.js`, shared constants in `RIDE` at the top of `src/ride.js`):**
- `susp.freq` / `freqR`: ride frequency front / rear (tyres included). Cruiser 1.35 / 1.45 Hz, Pickup 1.40 / 1.50, Rally Sedan 1.65 / 1.75 (was 1.40, 1.45 and 1.70 on both axles).
- `susp.zeta` / `zetaR`: low-speed bump / rebound damping ratio. Trucks 0.34 / 0.55, Sedan 0.40 / 0.65 (was 0.30, 0.32, 0.36 both ways).
- Two-slope dampers: firm up to a 0.25 m/s shaft-speed knee, then half the slope (bump and rebound); bump and rebound blend over the first 0.02 m/s so a joint at rest doesn't flip its damping every step (flipping it made the Sedan's wheels kick at rest).
- `tire.rate`: vertical rate of one tyre (N/m): Cruiser 280, Pickup 270, Sedan 220 N/mm. The tyre is in series with the spring: the ride rate is the spec frequency, the spring alone is stiffer (`kS`), and the bump stop's rate can't exceed the tyres'. Tyre pressure does not scale it yet (see *Open problems*).
- Bump stop over the last 40% of bump travel: rising rate (to 8x the ride rate, in series with the tyres), unloading gives back half its force (hysteresis), hydraulic damping while compressing, and position-sensitive rebound damping while leaving it. In the last 15 mm before the hard limit a very stiff, heavily damped "crushed stop" brings the axle to the limit slowly, so the limit no longer pushes back.
- Droop strap over the last 30 mm of droop (rising rate plus rebound damping): no hard top-out.
- Solid-axle roll: each side's damper works at its own shaft speed; roll damping = both dampers x `rollDamp` (1.1, was 1.4 on the symmetric damper). `susp.springSpacingR` lets the rear springs sit further in (Cruiser 1.10 m, Pickup 1.11 m against 1.15 m in front) so the stiffer rear doesn't cost articulation.
- Every vehicle collider has restitution 0 with the Min rule, so nothing it touches can make it bounce.
- Garage: Springs scales both `freq` and `freqR`, Damping scales both `zeta` and `zetaR` (same multipliers as before, so saved setups mean what they said).

## Auto-clutch stall assist and the fair ledge test

- **Pickup square ledge, traced:** at crawl pace the truck stalls at the lip with the auto-clutch slipping (engagement 0.16 at 1330 rpm, throttle 0.6). There the slipping clutch already passes everything the engine makes, but the Pickup's V6 (peak at 4600 rpm) makes little at 1330 rpm: about 155 N·m, 7,600 N·m at the wheels. Before the static hold, patch chatter broke it loose by luck: 0.30 m passed from 2 of 8 start positions. The hold removes the chatter and adds a little resistance (about 0.02-0.05 more throttle needed), so it always stopped at 0.25 m. The Cruiser's 0.45 m square crawl was luck too (3 of 8). The hold is unchanged.
- **Fair test** (`test/ledgeclimb.mjs`): every height is driven from 8 start offsets (0 to 0.5 m) and counts only if at least 6 clear it; the pass count per height is printed, and crawl cases report the lowest throttle cap that clears the limit height and the next one up. Runs in parallel processes, about 25 minutes on 12 cores. `LEDGE_ASSERT=1` checks the measured majority limits.
- **Stall assist** (`step` in `src/drivetrain.js`): with the auto-clutch slipping, the driven wheels slower than 0.3 rad/s in the gear's direction (stopped against something, or rolling back against the gear) and at least 15% throttle for 0.3 s, the clutch eases the revs up to the full-bite rpm for that throttle (`biteRpm`, the existing top of the bite curve, so it still rises with throttle) by passing the engine's torque less what it takes to raise the revs (at most 15% held back, 0.5 s time constant). The torque at the wheels then grows to the engine's torque at that rpm until the tyres climb or spin. It only starts if the engine's torque at `biteRpm` beats what the clutch passes now by 15% (at light throttle the idle governor props up the lugging engine, and easing off there made hill starts roll back), stays on while the wheels stay stalled, fades in over 0.5 s and out over 0.25 s. Zero throttle, pull-aways and the parking brake are unaffected; it never pulls the revs below `biteRpm`, so it cannot stall the engine. Still one exact boxed solve.
- **Ledge numbers on the clutch branch alone** (crawl / run-up, majority of 8; before = c18ccfa; the merged numbers are in *Integration pass*): Pickup square 0.35 / 0.35 m (was 0.25 / 0.35), chamfered 0.65 / 0.65 m (was 0.60 / 0.60); Cruiser square 0.40 / 0.60 m, chamfered 0.70 / 0.75 m (unchanged; 0.45 m square crawl clears 1 of 8: it hangs up with all four tyres spinning, a grip limit, not the clutch); Sedan square 0.20 / 0.25 m, chamfered 0.30 / 0.35 m (unchanged; its old 0.25 m square crawl was luck, 3 of 8 then, 4 of 8 now). Min throttle at crawl: Pickup 0.60 at 0.35 m square and 0.65 at 0.40 m; Cruiser 0.25 at 0.40 m square (no throttle clears 0.45 m).
- **Other numbers on the clutch branch alone** (before = c18ccfa): trails 400 s: Cruiser 5/5 (137 / 137 / 182 / 170 / 233 s; Widowmaker was stuck at 97/144 m before), Pickup Pinyon 159 s, Granite 173 s, Bog 194 s, Widowmaker 173 s, stuck in Boulder Alley at 51/180 m (same before), Sedan Pinyon 73 s and Bog 73 s, stuck in Granite 21/142, Boulder 55/180 and Widowmaker 24/144 (same before within a metre). ## Parked trucks and the parking brake (fixes)

- **Static hold** (`postPhysics` in `src/vehicle.js`, `cfm` rows in `src/drivetrain.js`): a braked truck used to slide 1-2 cm/s down 3-7° slopes with locked wheels (gravity acts inside the engine's step before the tyre solve, and four stiff patches on one rigid chassis chattered at the full mu x N in their free "squeeze" modes). A patch standing on fixed ground (under 0.04 m/s, not counting the gravity kick of the step just taken) now measures its slip on the chassis, gets a tread-like compliance, cancels the gravity it is about to receive and takes back 10% per step of how far it has slid since it stopped, all within mu x N, so slopes past the tyres' grip still slide. Its anchor is keyed by wheel + `oh` (the handle of the collider the patch stands on): a new patch type should set `oh` to a stable id of what it stands on. Without one it is keyed by its index in that step's patch list, so it never shares an anchor, but it re-anchors if the list order changes. `node test/slopehold.mjs`: every rig, rock and dirt, 4-22°, nose-up and side-on, parking / foot / both brakes: at most 2.5 mm in 40 s (was 14-124 cm); 30° mud still slides.
- **Parking brake vs 4-Low**: it now works through the range and axle ratios (a driveline drum ahead of the transfer case) and is sized to hold the engine's full torque in first with 10% to spare, never weaker than the old 1.5 x brakeT per rear wheel in high range (the Pickup is unchanged in high range; the Sedan is about 7% and the Cruiser about 57% stronger there, which also applies to the B handbrake). `node test/parkbrake.mjs`: 1st (4-Low where fitted) at 30/60/100% throttle holds every rig (was: the Cruiser drove off at 60%, the Pickup at full throttle at 21 km/h), with no stall. The "Parking brake is on" toast in `src/main.js` now repeats whenever you hold over 30% throttle in gear with it on (it used to need over 60% and under 1 km/h).

## Tyre pressure: on-board inflation

Before: one on / off switch, `car.airedDown` (T, only below 3 km/h; 10 psi vs 32 psi). Aired down it multiplied rock grip by 1.15, sand grip by 1.12 and sand rolling resistance by 0.55, mud grip by 1.06, rolling resistance on every other surface by 1.25 (`tyreGrip` in `src/vehicle.js`), widened (x1.12) and lengthened (0.06 -> 0.20 m flat patch) the mud footprint (`src/mud.js`) and took the deep-sand numbers from the "aired" column of `DEEP` (`src/deepsand.js`). The HUD had an AIRED lamp.

**Model** (`src/tyres/pressure.js`, headless):
- One live pressure for all four tyres. The CTIS moves it towards a target: 2 psi/s deflating, 1 psi/s inflating (compressor), at any speed. Stops per rig: min / crawl / trail / road / max. Tap `[` or `]` (under 0.3 s) for the next stop, hold for any pressure (it stops where you let go), T toggles crawl / road, Air- / Air+ on the tyre board tap.
- Air fraction f = (1/psi - 1/road) / (1/crawl - 1/road): the contact patch goes as load / pressure. f = 0 at road pressure, exactly 1 at crawl pressure (10 psi), 1.36 at 8 psi, -0.05 at 36 psi. Every old aired-down number is now `mix(up, down, f)` = up x (1 - f) + down x f, so 32 psi is the old aired-up tyre and 10 psi the old aired-down tyre to the bit, with everything in between continuous and a little more below 10 psi. `car.airedDown = true / false` still works (sets crawl / road pressure).
- Rock: mu x mix(1, 1.15, f): +5% at 18 psi, +15% at 10, +21% at 8. Mud: grip x mix(1, 1.06, f), footprint width x mix(1, 1.12, f), flat patch mix(0.06, 0.20, f) m. Sand: grip x mix(1, 1.12, f), rolling resistance x mix(1, 0.55, f); deep sand sinkage, digging, resistance and grip loss all mixed the same way. Hard ground: rolling resistance x mix(1, 1.25, f).
- Deflection: the loaded radius drops by defl x R x f x (load / static load)^0.8 (load filtered over 0.08 s; defl 0.06 for the trucks, 0.045 for the sedan): Cruiser at rest 1.0 cm at 18 psi, 2.7 cm at 10, 3.6 cm at 8. The physics tyre (wheel collider radius, patch point, mud bottom point) only takes the part below crawl pressure (`PHYS_DEFL_FROM = 1`): 1.0 cm at 8 psi, where the truck then sits 0.9 cm lower. Above crawl pressure it is drawn only (the whole truck drawn that much lower so the flattened tyres meet the ground). Why: with the whole deflection in the physics the ledge limits moved (Cruiser square run-up 0.65 -> 0.60 m, Rally Sedan square 0.25 -> 0.20 m) and other work is measuring them on the crawl-pressure tyre. Set `PHYS_DEFL_FROM = 0` to put it all in the physics.
- Costs at speed, faded in between 40 and 70 km/h (`SPEED_GATE`; zero below 40 km/h, so crawling, the trail autopilot and the 30-34 km/h run-ups of `test/ledgeclimb.mjs` are untouched): extra rolling resistance 0.012 x f at 70 km/h; sideways compliance 8e-6 rad/N x f on the rolling tyres' sideways rows (cfm = c V / h: lower cornering stiffness); steering rate x (1 - 0.3 f). Heat builds when faster than `safeKmh` = 12 + 2.6 psi (38 km/h at 10 psi, 59 at 18) and cools slowly.
- Bead: below the bead pressure (14 psi, sedan 16) and above 40 km/h, sideways force over 0.4 x load on a tyre builds bead stress (2.5 x softness x excess per second, softness = (bead - psi) / (bead - 6)), a hot carcass adds to it, and a side hit (sideways contact force, 25 ms filter, over 2.2 / softness x static load) pops it at once. The bead lets go: `health.tire` 0.3, the existing flat-tyre model (grip x 0.6, rolling resistance x 3, the wheel sags), a toast "Bead popped: ... Backspace repairs". Repair (Backspace, Y, spawn points) fixes it and keeps the pressure. A deterministic threshold, not a dice roll.

## Winch and recovery points (`src/winch/`)

Getting stuck is gameplay now: hook a line to a tree, a big rock or a recovery post and winch out.

**Design as built**

- **Line physics** (`src/winch/winch.js`): a one-sided soft constraint between the fairlead (a chassis-local point from the spec) and the anchor. It is ONE more row in `extra.rows`, the rows `Vehicle.postPhysics` hands to `Drivetrain.step`, so the winch, the tyre grip, the brakes and the engine are solved together in the existing exact boxed solve (`src/drivetrain.js` is not touched). The row acts on the chassis DOFs only (world linear 7-9 and body angular 10-12, like the grip rows) at the fairlead, so a pull pitches and yaws the truck; nothing goes into the light axle or wheel bodies. Impulse bounds `[0, rated pull x h]`: a line only pulls, and never harder than its rating. Softness: a spring-damper scaled to the truck's mass (`FREQ` 2.5 Hz, `ZETA` 1.0), written as a constraint-force-mixing term plus a position bias (a soft constraint); slack is speculative (rigid). The row is left out entirely while the line is slack, or while the fairlead is already closing on the anchor faster than the line needs (`v0 >= 0`), so a stowed or slack winch adds no row and the physics is bit-identical (tested). The drum: winching in shortens the line at the line speed (slower under load: `SPEED_FREE` 0.75 m/s down to `SPEED_RATED` 0.15 m/s); at the cap the drum stalls (`STALLED` after 0.25 s), the line never snaps in v1; paying out lengthens it at 0.6 m/s; with no command the drum brake holds (capped too). The line is never allowed to sit further inside the fairlead-anchor distance than the cap can hold, so a stall or an overload never winds up stretch that could come back as a jerk. Pull per drum layer: rated with all the line out, 70% with the drum full (`LAYER_MIN`).
- **Ground in the way:** the line may bend over ONE crest, the highest point of ground or fixed rock poking through the straight line (found with downward Rapier rays every 4 steps), which then acts as a fixed pulley: the force on the truck points from the fairlead to the crest, and the length is fairlead to crest plus crest to anchor. An anchor whose line would cut the surface again after that bend, or that has a trunk, rock or prop across either leg, is refused when picking. (The simpler robust option of the two: one crest, no rope wrapping.)
- **Hard-won rules kept:** Rapier still does normal contacts only; no torque impulses on link bodies; the static tyre hold is untouched (a braked truck against the winch holds within mu x N; past that it slides and the hold lets go by itself, as on a steep slope).
- **Anchors** (`src/winch/anchors.js`): fixed trees (not cacti or yuccas; strap at 0.6 m), fixed rocks at least 1.0 m across and 0.6 m tall (not ledge slabs or embedded relief; never loose stones under `DYNAMIC_MAX_WIDTH`), the dressing's fixed boulders, and the recovery posts. Offered: within the line's reach (less 0.4 m), 3 m or more away, within 80 degrees of straight ahead, line clear (above). Sorted by how well placed they are: near straight ahead and about 0.55 x the line length away, posts first among equals. Up to 8 at once; at most 16 are checked per refresh (each check casts up to about 100 rays).
- **Recovery points** (`src/winch/recovery_points.js`, derived from map data like `src/spawns.js`): cruxes found along every rated trail, The Gauntlet and its side courses and the race track (roads too, for bogs and fords): steps (the tread, ground or the top of a fixed rock, rising 0.3 m within 1.5 m), climbs (30% or steeper for 6 m or more, every 15 m on long ones), bogs and fords (the far bank, and every 15 m along a long one), and every Gauntlet stage / side-course section gate. Two-way trails are scanned both ways, The Gauntlet, the side courses and the race track in their driving direction. Each crux needs a post ahead of the stuck nose within 22 m (`REACH`), at least 5 m ahead and 3 m past the crux's top (`AHEAD`, `PAST_TOP`), no more than 2.5 m below the nose, in sight past trunks and props (a rock may stand up to 0.9 m above the line: the line bends over it). An existing post that qualifies is reused; otherwise one is placed beside the tread past the top, searched nearest-straight-ahead first, with a footprint check: inside the map, off every tread (0.7 m past the path's half width; 0.45 m as a last resort, for a trail on a causeway), no water or bog within a metre, ground grade up to 0.8 (1.4 where nothing flatter is in reach: a post driven into a bank), clear of every rock hull, trunk, box prop and loose prop. A crux that can't be covered is warned about in the console, never dropped silently (there are none now). Wide crawl corridors with marked lines (easy / hard / extreme) are scanned along each line, posts are tried outside the corridor's own width at their s, and a bog's or ford's post stands a truck length (5 m) past the far bank where it can. Counts, headless, on the merged maps: park 89 posts for 492 cruxes, race 3 for 4, crawl 91 for 252, jungle 80 for 144, desert 69 for 173. In the game the dressing's loose stones and logs are obstacles too, so the counts differ a little (the Gauntlet showed 65 in the browser). Built in 0.03-0.35 s at load.
- **Keys** (free ones; `src/winch/controller.js`): K tap shows the best anchor (a marker over it and a dashed preview line), each further tap the next one; hold K (0.45 s) hooks up to the one shown. U held winches in, O held pays out, L unhooks and stows. The motor runs only with the engine running; the truck may be in neutral or in gear with the driver helping (line and tyres share the solve). The board's buttons do the same (NEXT, HOOK; IN and OUT latch on and off; OFF).
- **HUD** (`src/winch/board.js`): a 112 x 46 board in the HUD's body text and text colours, a board of the pure layout (`BOARDS.winch` in `src/hud/layout.js`: above the chassis board, or bottom-right when that is hidden; dropped before the tyre board where there is no room), so toasts and big messages avoid it and `test/hudlayout.mjs` / `test/hudfit.mjs` cover it. It shows the state (Stowed / Aiming / Hooked / Pulling / Paying out / Stalled, blinking when stalled), the line out in metres, the load as a bar with a red zone from 85% of the rated pull, the anchor on offer while aiming, and its title reads Assisted during an assisted run. Only shown for a rig with a winch, while driving.
- **Look** (`src/winch/view.js`): recovery posts (dark steel post, gold band, collar ring at 0.75 m, a small footing), instanced. A drum and fairlead plate on the view's chassis group at the spec's fairlead point (so procedural and glTF bodies alike; re-mounted on every new view). The line in rope red as 28 thin segments: straight when taut, a parabolic sag sharing out the slack when not, over the crest when it bends; a hook at the anchor; a yellow strap round a trunk or rock. While aiming: a bobbing chevron and a ground ring over the candidate and a dashed preview line. The line and the preview are on the no-outline layer.
- **Audio hook:** the truck's winch, `car.winch` (where the engine audio's `audioStateFrom` reads it), carries `running` (the motor is commanded with the engine on, stalled included), `load` (tension / rated pull on the current layer, 0-1) and `direction` (`'in'`, `'out'` or null); `car.winch.state` is the HUD's state word (a string), so the audio uses `car.winch` itself. The same three fields are mirrored in `WINCH_AUDIO` (exported by `src/winch/winch.js` and `src/winch/index.js`, also `window.__game.winch.audio`), updated every physics step. `src/audio.js` plays it (motor and gear growl).
- **Rules:** a winch pull does not cancel a timed run. A run during which the line pulled (tension over 2% of the cap) is assisted: Trail Park trails keep `bestAssisted` beside `best` (for the session, like `best`); The Gauntlet and the side courses store the assisted best under `<key>.assisted.<rig>` and never let an assisted run replace the unassisted best or split records; race laps store `lowrange.bestlap.race.assisted.<rig>`. Toasts say "winch assisted" with the assisted best. Teleports, restarts and repairs (every `respawnFresh`, and a truck rebuilt in place by `Vehicle.reset`) unhook and stow the line; switching maps reloads the page.

## Engine, tyre and winch sound (`src/audio.js`)

User ask: heavier, deeper engine sound and no whine; better tyre sound.

**What the whine was** (measured offline on the old voice, `test/lib/audio_baseline.js`): one 2-revolution cycle of thumps, each a sum of pure sines (f, 2f, 3f, 5f with f = 40-66 Hz), looped perfectly and resampled with playbackRate = rpm / 750. So every component was an exact harmonic line, and the thump's own tone rode up with rpm (the Rally Sedan's 58 Hz thump sits at about 540 Hz at 7000 rpm) behind a low-pass that also swept with rpm. Result: a pure, rising buzz at 450-1000 Hz only 3-9 dB under the low note at 4000-5500 rpm (Sedan 458 Hz at -4.3 dB, Pickup 549 Hz at -5.1 dB, Cruiser 493 Hz at -9.3 dB) and narrow lines just above 1 kHz at -18 to -22 dB. The old voice was already dark by spectral centroid (58-104 Hz at idle and crawl); its problem was tone, not brightness. The 55-235 Hz "driveline" sine was too quiet to matter (about -48 dB) and is gone.

**Engine voice now:**
- Per rig from `spec.engine`: `sound` picks a profile in `PROFILES` (diesel = V8 diesel for the Cruiser, v6 for the Pickup, boxer for the Rally Sedan, v8 for the parked rig), `idle` and `redline` set the range, and optional `cyl` / `diesel` fields override the profile. No id checks.
- Three looping buffers per engine, built once at idle rpm (about 3 s of firing events, firing rate = rpm / 60 x cylinders / 2): DRIVE (firm pressure pulses plus a short combustion-noise burst), COAST (soft, wider, uneven pulses, about 1 in 7 nearly missing, the odd small pop on a petrol) and CLATTER (diesel knock clicks with their own timing jitter, or exhaust rasp on a petrol). Every event has a per-cylinder strength and timing offset (bank-to-bank lope on the V8, paired pulses on the flat four), timing jitter (4-5% of the interval), amplitude jitter, and each cycle's length wanders about 1.5%, so no order settles into a pure tone. The buffers are band-limited at build time so playback up to redline cannot alias.
- They play in lock step with playbackRate = rpm / idle (a pulse lasts a fixed crank angle, so it shortens with rpm like a real exhaust pulse).
- Body chain: soft saturation (more drive at high load and low rpm) -> three FIXED peaking resonances, exhaust / block / intake (low Q, never move; only the intake's gain follows load) -> a low-pass with no resonance (Q 0.6) that opens with load far more than with rpm, held to 45% of its opening in 4-Low under 10 km/h -> plus a fixed 85 Hz sub branch, strongest at idle.
- Load: `audioStateFrom(car)` computes load = engine torque / available torque, x0.4 in neutral. Effort = max(load, throttle / 2), smoothed (rises in 0.1 s, falls in 0.25 s so it does not pump), crossfades COAST to DRIVE and raises level, saturation and brightness.
- Tuning constants per rig (`PROFILES`): pulse width (fraction of the firing interval) diesel 0.7, v6 0.5, boxer 0.44; jitter 0.05; exhaust / block / intake resonances diesel 88 / 210 / 400 Hz, v6 105 / 270 / 620 Hz, boxer 96 / 250 / 600 Hz; low-pass closed / open diesel 280 / 820 Hz, v6 340 / 1400 Hz, boxer 360 / 1500 Hz; diesel knock 0.55, petrol rasp 0.3-0.34. No gear or transfer-case whine layer, no turbo whistle.

**Tyres and ground:** six looping textures built at start (brown noise, white noise, gravel grains, mud blobs with a downward glide, water swells) through fixed filters into one gain per surface: dirt / grass rumble, gravel crunch (plus some rumble), rock crackle (low-passed grains, audible even at walking pace), tarmac hum (kept low), sand hush, mud squelch (louder with wheel spin), water splash (plus rumble). The mix follows the share of grounded wheels on each material and the tyre surface speed. Scrub: per-wheel slip velocity over 0.35 m/s, weighted by load, on rock / tarmac / wood, through a 620 Hz band-pass with Q 0.9 (grainy, low-mid, no squeal); on loose ground slip adds crunch and rumble instead. Scrape: the rate of `car.crash.scrape` (the crash model's scrape work) drives a 420 Hz grain voice. The `clunk` (gear / locker / parking brake) is now a 78-38 Hz thud, `grind` a short gritty 700 Hz scrape (it was a 2.4 kHz Q 4 band-pass), `starter` a low churn.

**Winch:** `audioStateFrom` passes `car.winch` (or its `.state`) when present: `{ running, load 0-1, direction: 'in' | 'out' }`. The voice (a 40-46 Hz band-limited sawtooth plus a sub sine through a 260 Hz low-pass, and a 160 Hz gear growl that grows with load) is only built the first time such a state shows up. A DC motor slows under load, so the pitch drops as load rises.

**Mix, comfort and lifecycle:** engine bus and effects bus (settings: Engine volume, Effects volume) -> high shelf -8 dB above 4.5 kHz -> low-pass 7 kHz -> compressor (-12 dB, 4:1) -> master gain (Master volume, Mute sound in F10, the N key and the pause fade). All parameter moves are `setTargetAtTime` ramps; voices fade in, and a rig swap crossfades and releases the old voice when it ends. The AudioContext is only created once the page has user activation (a click or key), and resumed on the next gesture if the browser still holds it back. The pause menu fades out and then suspends the context (no CPU while paused; `update()` does nothing while suspended so ramps do not pile up); page hide (a map change reloads the page) closes it. `window.__audio` is a console handle. No AudioWorklet, so nothing changes for the Electron CSP.

**On-board air** (integration pass): a compressor (38-40 Hz band-limited sawtooth and its sub through a 220 Hz low-pass, plus brown-noise rattle at 150 Hz) while the tyres inflate and a vent hiss (white noise, band-pass round 900 Hz, low-pass 2.4 kHz) while they deflate, from `car.tyre.state`; `test/audiospec.mjs` checks both are low, have no narrow tone and are silent when the pressure has settled (compressor rms 0.058, centroid 66 Hz; vent rms 0.008, centroid 1.49 kHz).

**Cost:** 55 persistent nodes (engine voice 3 sources, 3 gains, 1 out; body chain 14; tyres 6 sources and about 22 filters / gains; master 7), plus 9 more once a winch exists and 12 more once a tyre state exists (always, in the game). Rendering 10 s of the whole graph offline takes about 56 ms per second of audio including building the buffers (under 6% of one core, on the audio thread); `update()` takes about 46 us per call on the main thread. Building one engine's buffers is a one-off when a drive starts.

## Wide crawl corridors

User request: crawls longer and much wider, BeamNG style: a broad corridor between a start and an objective with several lines to pick from, road-like where that makes sense.

**Model.** A crawl is a narrow, road-like tread (the gate width) that opens into wide areas and pinches again at gates. Inside a wide area, lanes run side by side, each a line of clearly different difficulty: `easy` (the rated line), `hard` and `extreme` (optional). Lanes split the corridor at the midpoints between their lines; the outer ones run to the edge. The rating of a trail or stage is its easiest complete route: the transit plus every easy lane. Everything is map data:
- Trail Park (`src/maps/trailpark.js`): `TRAIL_DEFS[].cruxes` ({ name, at, len, w, lanes, features }); after the build each trail has `corridor: true`, per point `w` (width), `sh` (edge fade), `xs` (cross slope: the hillside's own fall, limited by difficulty, so a wide corridor doesn't sit in a cut), `cruxes` with absolute `s0` / `s1` and lane bands { name, lat, lo, hi }, `lines` { easy, hard, extreme: [[s, lat], ...] every metre }, `lineAt(name, s)`, `laneLat(crux, name, s)`, `cruxAt(s)`. Ledge rocks carry `crux` tags { trail, crux, name, lane, kind, u, rise, lat } and their half sizes `hw` / `hd`; crawl-over rocks carry `crux.kind` over / crawl / kicker / notch. Exported `widthAt(trail, s)`.
- The Gauntlet (`src/maps/crawl.js`): `STAGE_DEFS[]` gain `widths` [[u, w], ...], `lanes` [[name, lat], ...], `laneZone` [u0, u1] and per-lane values ({ easy, hard, extreme }) inside the obstacle blocks; each stage gets `bands`, `open(u)`, `lineLat(name, u)`, `zone`; `TRAILS[0]` has `corridor`, `lines`, `lineAt`; `perLane(value, lane, k)` is exported. Step slabs carry `step` { stage, u, rise, grade, depth, lane, lat }, up-and-down ledges `gate` { stage, u, top, lane, lat }, rock gates `squeeze`, crawl-overs `over` / `crawl`, staircase seams `seam`, the Climb's ribs `rib`.
- Side courses (`src/maps/crawl_courses.js`): sections may have `lanes`; sections get `bands`, `open`, `lineLat`; courses with lanes get `lines` / `lineAt`. Per-lane camber ({ deg: { lane: [from, to] } }), kickers / axle holes by lane, the rib on the hard lane, cobble size and packing by lane (`cobbles.lanes`).
- Readability: through a crux the easy line's wheel tracks are worn darker (`GRID.tone`); where lines split, a pair of marker posts stands either side of each line's way in (the trail's colour for easy, black for hard, red for extreme) and a sign names the crux and its lines left to right ("LINES" on The Gauntlet and the courses). Corridor edges are boulders just outside the drivable width and a widened edge fade into the natural ground, not walls. The big map stamps each corridor as wide as it is (capped at 20 m) with the easy line as a pale thread.
- Staircases on The Gauntlet (Ledges I, Ledges II, the Waterfall): each lane climbs its own stairs to the same height (many low steps on the easy line, a few tall ones on the extreme line; rises scaled to the easy line's total), with boulders along the seams where the lanes' ground stands at different heights between steps. The trail profile follows the easy stairs; `stairOffset` lifts the other lanes.

**What assumed a narrow tread, and how it changed**
- Bake (park and Gauntlet): path width, edge fade and cross slope are read per point (`a.w`, `a.sh`, `a.xs`); roads unchanged. `GRID.path` covers the whole corridor, so "which trail am I on" (`main.js trailUnderTruck`), set dressing clearance (`gridClearance`: medium / large dressing rocks keep 0.8 m clear of every path, logs too), trees and scattered boulders all follow the wide corridor.
- Gates: the corridor pinches to the old tread width at each gate (park trail ends, Gauntlet stage gates, course section gates), so the gate posts and `updateTrails`' radius (`t.width / 2 + 2.5`) still span it; Gauntlet gate arches use the width at the gate (`st.gate.w`).
- `CrawlCourse.project` (`src/crawl_course.js`): "on the course" uses the width at the nearest point (`a.w`), not the stage's maximum.
- Marker posts and signposts (`world_view.js`, `crawl_view.js`): at the corridor edge, per point.
- Ledges: `rockKit.ledge` takes an optional cross slope (`side`), so a lane's slab follows the corridor instead of the bank past its edge.
- Spawns: step slabs' hull origin sits in the middle of their own lane (a slab spanning the width from the centreline had a 10 m footprint disc and blocked the stage 7 spawn); the Gauntlet's embedded relief stays out of the last 8 m before each gate.
- Bypass track: its offset grows where a stage is wide (half width + 9.25 m, at least 12 m); spurs follow.
- Rocks of one part of a park trail that land in the corridor of another trail, or of another part of the same trail more than 25 m away along it, are dropped. Wide parts sit only where the trail bends gently (bend radius at least the half width plus most of the edge fade), so a corridor never folds over itself.
- Autopilots: `test/trails.mjs`, `test/crawl.mjs` and `test/coursedrive.mjs` drive a marked line (LINE=easy|hard|extreme, default easy) and pick their way round boulders within 1.4-1.6 m of it; packed crawl-overs and low rocks are driven over.

## Ground relief, loose stones, log edging, tyre effects

- **Loose vs fixed** (`src/physics_props.js`): only stones under 0.4 m across (`DYNAMIC_MAX_WIDTH`) are dynamic; medium/large rocks, logs and stumps are fixed colliders. Dressing small stones are 0.16-0.34 m; medium/large ones keep 0.8 m clear of every path (`src/art/dressing.js`). The Gauntlet's loose stones (`LOOSE` in `src/maps/crawl.js`) are small and sparse on stages 1, 2, 4 and 5; it has no loose logs.
- **Logs** only as fixed trail-crew edging (`logEdging` in `src/art/dressing.js`): runs along the outside of trail bends tighter than 30 m radius, a pair at each trail entrance, and parking bumpers round the trailhead lot. Every log is 0.8 m + its radius clear of every path and sits on gentle ground. `test/props.mjs` (h) checks this on the Trail Park.
- **Relief** (real geometry): `lumps` / `potholes` in `src/maps/common.js` are baked into the 1 m heightfield; `rockKit.embedded` makes low, rounded, fixed rock hulls sunk into the ground for the sub-metre bumps (all embedded hulls share one fixed body). Gauntlet: per-stage `RELIEF` table (lumps, ruts, holes, embedded rocks in the wheel tracks, rubble beside the tread, rocks on the Ledges slab tops), faded out in front of every step and gatekeeper so `test/crawlcheck.mjs` step heights hold. Park trails: `RELIEF` by difficulty in `src/maps/trailpark.js` (green stays at or under 0.12 m). Open ground everywhere: lumps, sd 0.07 m. Roads and the bypass track: crown plus washboard / lumps / shallow potholes. Race track: washboard on straights, braking bumps before bends, potholes, a firmer swept line with loose gravel off it, and mud on the outer metre and verge around the splash. Bogs have churned ruts (60% visible). `GRID.tone` darkens ruts and mud in the ground shader (two calm steps, `src/gfx/terrain_look.js`). A finer heightfield was not used: the embedded hulls give the sub-metre bumps without a 4x bigger terrain mesh.
- **Deformable mud** (`src/mud.js`, `[mud]` blocks in `src/vehicle.js`): between each bog's shown surface (`GRID.vis`) and its firm floor (`GRID.h`, the heightfield) the mud now carries the tyres: bearing pressure k·z over a footprint that grows with sinkage and that airing down widens and lengthens, so heavy, narrow, hard tyres sink deeper (parked Cruiser 0.15 m, aired down 0.12 m, +800 kg 0.18 m). Sinkage costs compaction resistance (b·k·z²/2) and viscous drag, the belly and solid-axle diffs drag and carry weight once they reach the mud (high-centred), and the tyres grip through a contact patch carrying the mud's load. Driving works a 0.2 m lattice kept only over the bogs (`MudField`, attached as `terrain.mud` by `src/terrain.js`): ruts pressed by each tyre (they stay, and every pass churns the mud softer so they deepen), holes dug by spinning wheels (spin = digging, not help), berms beside the ruts. Vehicle functions: `mudPre` (support, plough, drag), `mudBelly`, `mudPatches` (grip), `mudWork` (ruts / churn / digging); outside the bogs nothing changed. `node test/mud.mjs` checks it (load, airing down, spin vs roll, ruts deepening and persisting, a locked 4-Low Cruiser crossing Bog Run while a 2WD open-diff full-throttle attempt bogs (47/116 m after the review fixes), and that the damping stays stable in the worst case).
- **Tyre effects** (`src/fx/tyre_fx.js`, one call each from `src/main.js`, marked `[tyre fx]`): two pooled, instanced particle systems. Lumps: mud thrown off the tread tangentially once it spins fast enough to shed it (more with wheelspin, a bow wave when ploughing at speed), 1-8 cm irregular blobs and streaked flecks that land as splats and soak in; water drops and splash in fords; grit from spinning tyres; crash flakes. Puffs: dust on road / dirt / sand / gravel (each its own dryness), in proportion to speed and wheelspin, tinted from the ground's ramp lifted towards the haze, hanging longer behind a fast car, faded within 2-5.5 m of the camera and where they meet the ground; also engine smoke / steam and water mist. Counts scale with the graphics preset. The bogs' surface is `src/fx/mud_view.js` (a 0.2 m mesh per 6.4 m tile that follows the mud state; under the bogs the terrain mesh drops to the firm floor, `baseVertexHeight`). Mud on the truck: `src/fx/mud_coat.js` via the toon patch (tyres cake, the lower body takes spray, fords wash it off, it dries paler). `CHROME=... PORT=... node test/mudshots.mjs <outdir> [bog,ruts,crawl,splash,road,race]` captures the scenes (PERF=1: frame cost only, PX=4: Chunky pixels).
- (Older autopilot numbers from the relief work are superseded by *Wide crawl corridors* and *Integration pass*.)
- **Trail ends** (`buildPath` in `src/maps/trailpark.js`): both ends stay pinned to the road height and the grade limit reshapes the approach (it used to lift the far end, leaving 3-5 m drops into the road at Pinyon, Bog Run and Widowmaker). `MAP=park node test/spawns.mjs`: all ten trail-end spawn points, no warnings.

- **Size and grid:** 1200 m square on a 2 m grid (601² vertices: 1.6x the Trail Park's vertex count for 9x the area). Sub-metre relief on the crawls is rock hulls, as elsewhere. Fog 240-1150 m and camera far 2600 m are set by the view; the backdrop rings scale with SIZE.
- **Look:** the map swaps the ground ramps when its module loads (`RAMPS`: apricot dune sand, grey-brown floor, red slickrock, bone dry lake; MAT_INFO colours for dust and minimap; sky bands; backdrop), so nothing in `palette.js` changes for other maps. `GRID.look` tells `terrain_look.js visualSurface` what the ground shows off the paths (desert floor, gravel pavement, rock) instead of grass.
- **Dune route:** `duneRoute()` runs A* between waypoints over the raw sand (uphill ≤ 0.30, downhill ≤ 0.68 head-on, side slope ≤ 0.24), so the marked route stays drivable if the dune shapes change. The route is a trail with `graded: false`: no carving, not on `GRID.path`; `test/trails.mjs` skips it.
- **Deep sand:** only where the map exports `sandDepthAt` (Vehicle builds a `DeepSand` only then, so every other map is bit-identical). Hooks in `vehicle.js`: the per-wheel terrain loop (sinkage, resistance force, scaled viscous Sand drag) and the patch grip (mu and sideways cap). The static tyre hold works on dune sand too, inside the sand's sideways cap: a parked truck holds on flat sand, across the 15° face and (at the limit) a ~22° face; across a 32° slip face the cap is exceeded, the tyre slides and the hold lets go by itself. Dune-sand rows get the hold's compliance (soft sand: no stiff squeeze modes eating the grip during a slow slide). Sinkage costs traction, not sideways hold; digging comes from wheelspin (spin slip), not from sliding sideways. Ground patches keep their `oh` (the heightfield's collider handle). A repair (rebuild) clears the sinkage. `test/sand.mjs` asserts all of this per rig, aired up and down (`PARK_ONLY=1` for just the parked cases). Tuning in `DEEP` at the top of `src/deepsand.js`.
- **View:** `src/desert/view.js` is a map view module (`buildDressing(trees, { scene, camera, sun })`, `update(camera, t, car, dt)`, `clear()`), loaded lazily through main.js's `MAP_VIEWS` seam with the jungle's: the desert dressing, sky and light, dune shading on the terrain mesh, and the sand tyre marks (their own mesh, uploading only the changed range; the dust in `src/fx/tyre_fx.js` marks nothing on the ground). `clear()` runs beside the mud reset (fresh start, trail restart, spawn-point teleport; not a repair in place) and wipes the marks. ## Known gaps

- Mud limits: the mud's support on a tyre is always vertical and the berms only raise the surface, so ruts don't steer a truck or hold it in its track (no sideways rut guidance), and a tyre climbing out of a rut gets no extra resistance. The rut lattice is 0.2 m. Mud packs on the tread only as a look (no grip loss from clogged tread). The belly reads `spec.chassis.floor` (chassis-local floor-pan height) when a spec has one, else the frame box's bottom.
- Crash model limits: the collision shape stays boxes (only shrinks a little as ends / roof crush), the deformation is visual + a cage, not a soft body; rollover damage depends a lot on how the tumble goes.
- The Rally Sedan's collision now follows its model's underside (`chassis.floor` in `src/specs.js`, boxes in `src/vehicle.js`): floor pan 0.25 m, sills 0.30 m, front bumper 0.27 m (the 0.19 m splitter lip is trim and has no box). Before, its lowest box sat at 0.39 m, 0.14 m above the body you see. Green rocks stay capped at 0.20 m.
- Desktop builds are unsigned (SmartScreen warning).

### Wide crawls (Coralume Island and Sunfall Basin, latest)

The rated crawls on both maps are now BeamNG-style crawl areas: a broad corridor of obstacles between one start gate and one finish gate, where each crux has two or three lines side by side and the rating is that of the easiest complete line. Built by `src/maps/widecrawl.js` (used only by `jungle.js` and `desert.js`):

- **Model.** The centreline is the EASY line and stays the reference path (progress, Y restart, autopilot, waypoints). `t.width` is still the gate mouth (each trail's old width), so gates, their spawn points and the road junctions are as before. Each path point carries the corridor half-widths `wl` (+lat side) and `wr`; the bake labels the whole corridor as the trail on `GRID.path`, so anywhere in it counts as "on the trail" (Y, which-trail logic, map stamps). Off the easy line the corridor follows the ground's own cross-slope within limits (`cross` per trail), and its edges fade into the ground over a wider shoulder.
- **Cruxes** (`crawl.cruxes` per trail, resolved into `t.cruxes`): lanes side by side, each with one feature: `ledge` (skewed, so they can be taken at an angle, with room to turn in front), `boulders` (a rock garden; the easy lane keeps its line clear at least 3.5 m between rocks), `slab`, `camber` (an off-camber shelf), `holes` (cross-axle holes), `notch` (V-notches), `crawl` (rocks in the tyre tracks), `fin` (a rock wall splitting channels), step bands (`wideStep`: one slab per lane across the whole band, big rocks locking its ends). Every placed feature is listed in `t.cruxes[i].features` (type, line, s, lat, height) for recovery points and tests. `t.lines.easy|hard|extreme(s)` give each line's lateral offset (held through each crux, lined up 5 m before it, blended between cruxes, back on the centreline at the mouths and wherever the corridor pinches near a road). `t.halfWidthAt(s)`, `t.pinAt(s)`.
- **Roads untouched.** Within reach of a road (Riverbed Run beside and through the Plantation ford) the corridor pinches to its mouth, and on a road's tread a wide crawl bakes and scores exactly as the narrow trail did: the road surfaces differ from before only at the two new junctions (Cliffside Ledge's new west end on the Coast Road, Coyote Wash's new end on the Basin Loop) and by up to 0.12 m on the outer edge of Plantation Road by the creek; the Coast Road bridge pass gives its old numbers.
- **Readability.** The easy line is worn lighter than the corridor round it (`GRID.tone`); slabs and shelves are bare rock; a pair of short posts flanks each lane where a crux begins, topped white (easy), amber (hard) or red (extreme) (`src/art/jungle/view.js linePosts`, `src/desert/view.js`); on the island the marker posts stand on the corridor edges and the jungle stands 6.5 m back from wide crawls. On the desert the shared `world_view.js` marker posts still stand at the gate-mouth width either side of the easy line (no colliders).
- **Heights** tuned to the measured square-ledge limits at crawl pace (Cruiser 0.40 m, Pickup 0.35, Rally Sedan 0.20) with a margin: green easy lines 0.12-0.16 m (crawl rocks under 0.2), blue easy 0.26-0.30, black easy 0.26-0.32, double black easy step faces capped at 0.36 (island) / 0.38 m (desert, the rest of each band's rise is a ramp behind the face); hard lines 0.26-0.30 (green), 0.36-0.42 (blue, black), full band rise to 0.5 (double black); extreme up to 0.42 (green), 0.50-0.55 (blue, black), 0.6 (double black). The hard and extreme lines are optional bonus lines; rigs are not expected to clear them all.
- **Tests.** `MAP=jungle|desert node test/widelines.mjs [rigs] [secs] [trail]` drives a chosen line (`LINE=easy|hard|extreme`, default easy) with the `test/trails.mjs` autopilot (no flip resets); `... widelines.mjs audit` lists every crux, lane and feature, the corridor width range and the tallest rock under each line's tyre tracks. `MAP=... node test/crawlpreview.mjs <outdir> [prefix]` writes top-down PNGs (rocks coloured by height in 0.15 m steps, easy line white, hard orange, extreme red); before / after previews in `docs/previews/widecrawl_*`. The long trails need about 500-750 s at the autopilot's crawl pace, so `test/trails.mjs ... 400` (or 300 on the desert) reports Cliffside Ledge, Coyote Wash and Whaleback Slickrock as stuck when they are simply out of time: use a 1000 s budget.
- **Cost.** Island: 1839 rock hulls (954 embedded on the shared body, 885 fixed bodies; was 1090 / 331 / 759), 3595 trees (was 3719), bake 2.55 s vs 2.16 s measured side by side. Desert: 2665 hulls (1446 embedded, 1219 fixed bodies; was 1588 / 661 / 927), bake 1.95 s vs 1.56 s. Frame cost not measured in a browser.

## Repo hygiene

- Public repo: github.com/RMamujee/LowRange. Commit as `RMamujee <133895954+RMamujee@users.noreply.github.com>`, with **no AI co-author lines**. Run gitleaks before pushing.
- `.claude/`, `node_modules/`, `release/`, `test/shots/` and `Claude outputs/` are ignored.
- `.blend` files: Blender stores local paths in them (the stock Shading workspace's File Browser folder, the absolute path a texture was packed from). `node test/blend_paths.mjs` fails on any absolute path or user name in a tracked `.blend`. Build scripts save through `tools/blender/blend_save.py`; to clean a hand-edited file, run `blender --background --factory-startup <file.blend> --python tools/blender/blend_save.py`.
- Local paths in text files and PNG metadata: `node test/local_paths.mjs` fails on any absolute user-home path or the current user's name in a tracked text file or PNG text chunk; write paths in docs as `<home>\...`.
